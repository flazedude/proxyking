# Game accelerator redesign

Status on 2026-11-01: v0.4.0 implements the first installed game library, real artwork, read-only game discovery, exact executable scopes and supported server-only Clash import using the existing engine. The owner chose **open-source-only** routing components, accepting additional driver/signing work. Commercial SDKs are excluded from the implementation path.

The first installable version deliberately retains the existing routing backend with a conservative native Clash-process guard. It blocks new non-local connections while Clash is detected and monitors active non-local sessions, stopping only ProxyKing's engine when needed. It does not claim the future backend's simultaneous-tunnel guarantees. Release gates below concerning a new interception driver remain applicable to that later backend; they do not prohibit publishing the requested library/artwork/discovery iteration with documented existing-engine limits.

## Original standalone prototype

```powershell
npm ci
npm run dev:accelerator
```

Open [the game accelerator preview](http://127.0.0.1:1421/accelerator.html). To produce the separate static preview, run `npm run build:accelerator`; output is `dist-accelerator/accelerator.html`. The normal desktop/browser entry remains `index.html`, and the normal `npm run build` does not package the accelerator preview. The prototype also refuses to render its controls inside Tauri.

The preview has Play, Library, Servers, Activity, and Settings pages. Games, launchers, and manually entered executable paths have independent selectors. Steam, Battle.net, Epic, Riot, EA, Ubisoft, and GOG are sample launcher cards. Launcher-only, specific-game, and launcher-with-children selections are explicit. The session panel deduplicates full paths case-insensitively; selecting a game never implicitly adds its launcher or sibling games. Native process enumeration, installed-game discovery, file existence checks, launch actions, elevation, acceleration, and update downloads are absent.

The original concept used CSS geometry; it now shares the real poster/brand renderer with the installed interface. Publisher posters are loaded remotely, with pinned Simple Icons glyphs bundled for supported brands. Sample install paths begin with `C:\Example Games` or `C:\Example Launchers`. Sample servers have no endpoints or credentials. All sample content is identified in the interface. Server latency and traffic show unmeasured placeholders, not fabricated measurements. Game names illustrate the interface; they do not claim routing or anti-cheat compatibility.

YAML import is **metadata only**, not a working profile import. It uses pinned `yaml` 2.9.1, a development dependency. The import report contains server names, types, and an unverified/disabled UDP label; endpoint details, passwords, UUIDs, provider URLs, raw nodes, and controller credentials are not retained in the report. The YAML text exists in the import dialog's memory until dismissal. No browser storage, network fetch, native invocation, provider-file access, script execution, config export, or connectivity test occurs. Reload discards all user changes.

The importer checks UTF-8 byte size (512 KiB), YAML document structure, duplicate keys, tags, aliases, mapping keys, nesting, node count, and a 500-server limit. Parser errors use fixed messages, never source excerpts. Direct proxies and inline provider payloads can supply labels. External/incomplete providers are reported without fetching them; groups are counted and unresolved references reported but are not executed. The recognized protocol labels do not establish engine compatibility or valid remote authentication. Other config fields are discarded, with known system/routing/controller sections summarized in the report.

## What the current native implementation actually does

`src-tauri/src/config.rs` creates a sing-box TUN with automatic IPv4/IPv6 routes, then uses full executable-path rules to select the proxy outbound and sends unmatched traffic direct. This is selected-process **proxy routing**, not capture restricted to those processes. It changes the machine's routing path and cannot be represented as proven safe alongside an independent Clash TUN. Current validation explicitly has not exercised elevated live TUN capture.

Mihomo's documentation similarly distinguishes [full-path process rules](https://wiki.metacubex.one/en/config/rules/) from [automatic global TUN routes](https://wiki.metacubex.one/en/config/inbound/tun/). Changing adapter names, listener ports, or engine brands does not resolve capture precedence, fake-IP DNS, carrier interception, or proxy loops. An unselected application should retain its existing Windows/Clash behavior, which may already be proxied by Clash; calling it "direct" would be misleading in this coexistence design.

## Routing feasibility result

**A plausible open-source path exists, but no candidate is release-qualified for this application.** The next implementation experiment should assess a separately supervised, adapted ProxyBridge/WinDivert carrier feeding an app-owned loopback SOCKS listener. That is a candidate for selected-executable proxying without introducing a second automatic TUN route set. It does not yet prove that unrelated traffic is untouched or that Clash TUN coexistence works.

ProxyBridge source was cloned for read-only inspection into a temporary research directory outside this checkout. Nothing from it was built, executed, installed, or vendored. No third-party driver was loaded. Relevant pinned files:

- [Public C API](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/ProxyBridge.h): proxy/rule setup, traffic callbacks, start/stop. A dedicated helper process is preferable to loading this core into the Tauri process, so native supervision can own its lifetime.
- [Rule matching](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/pb_rules.c): path-form rules match the full path case-insensitively when no wildcard is present; also permits broad patterns and multi-entry syntax that the application must never generate accidentally. Separator, Unicode, extended-path, delimiter, and long-path compatibility need explicit regression coverage.
- [Process lookup](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/pb_process.c): queries Windows image paths but has basename fallbacks and fixed-size path buffers. A selected full path must not degrade to a basename match, and long paths must not become truncated matches.
- [Socket map](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/pb_sockmap.c): observes socket-connect events; this does not establish correct attribution for every unconnected UDP send or PID/port reuse scenario.
- [Packet engine](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/ProxyBridge.c) and [upstream flow description](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/README.md#how-it-works): the network capture scope is broader than selected executables; unrelated packets are handled and reinjected. This is materially different from claiming only selected flows enter the component.
- [Internal relay constants](https://github.com/InterceptSuite/ProxyBridge/blob/2eb007671c82c972821e8e9bd404bc82499ebb4f/Windows/src/pb_internal.h): the UDP relay uses fixed port 34011. Adapt this to application-owned available ports before integration; merely changing the main SOCKS port is insufficient.
- [WinDivert documentation](https://github.com/basil00/WinDivert/blob/master/doc/windivert.html): the network layer does not provide a process ID; ownership must come from another layer or OS queries. Its driver signing, filter priority, queue/drop behavior, and interoperability require independent qualification. Reusing an unmodified upstream signed driver may avoid signing a custom kernel binary; the actual pinned release, signature trust, Windows policy, and distribution obligations must be verified before choosing that route.

## Required native architecture

1. UI selection resolves to an explicit normalized set of full executable paths. Native state remains authoritative. Launcher child expansion stays opt-in, visible, and distinguishable from exact game selection. Existing selections and child preferences must migrate without silent broadening.
2. A separately supervised interception helper accepts only application-generated rules and a private loopback proxy endpoint. It must not load arbitrary rule files, subscribe to external controllers, mutate another application's service, or stop processes by basename. A restricted IPC contract, own single-instance identity and Job Object, explicit elevation, reliable stop acknowledgments, and crash recovery are prerequisites.
3. An independently packaged proxy engine owns its private ports, random controller secret, runtime directory, caches, and encrypted app data. Broad Clash node support favors Mihomo, but secure configuration handoff and migration of existing profiles must first match the current DPAPI/no-plaintext-config contract. Do not pass secrets on a command line or write persistent plaintext engine configs as a shortcut. Keep the current engine until a tested replacement is ready.
4. Import only the server graph supported by the selected engine. The application constructs routing/listener/controller settings; a provider export cannot enable global TUN, system proxy, DNS hijacking, arbitrary file access, or scripts. External provider fetching is a separate native feature with bounded content, explicit destinations, private storage, safe path handling, redaction, and no silent loss of meaning.
5. Exclude the application, its helpers/engine, and Clash carrier processes from our proxy rules. This alone does not prevent Clash from intercepting our engine. Evaluate outbound interface selection, fake-IP destinations and DNS ownership without changing Verge settings. If a combination is unsupported, stop our connect attempt with an actionable explanation.
6. Keep direct fallback as the current documented behavior; no kill switch is added implicitly. Explain cases where process ownership or protocol support is missing. No claim that DNS from a shared Windows resolver belongs exclusively to a selected game.

## Release gates

- Reproducibly build the chosen user-mode component; pin its exact source, upstream driver artifact/hash/signature, licenses, and corresponding source. Source audit is not binary verification.
- Test exact path identity against same-name binaries in different directories, Windows casing/separators/Unicode/long paths, unknown owners, PID reuse, port reuse, launchers, grandchildren, service-launched games, and connections created before selection.
- Exercise authenticated upstream TCP and UDP, connected and unconnected UDP, multiple UDP destinations from one socket, IPv4/IPv6, MTU/fragmentation, DNS/fake-IP behavior, loopback exclusions and carrier loop prevention. Mark protocol limitations honestly.
- On an isolated Windows test machine, compare selected-game exit and unrelated-app behavior with Clash absent, open but inactive, system proxy active, TUN active, and Clash mode changes mid-session. Compare proxy settings, routes, DNS, and third-party service state before/after. Add relevant anti-cheat compatibility checks; no DLL injection or compatibility claim by inference.
- Test disconnect, app exit, engine/helper crash, queue saturation, sleep/resume, network change, repeated start/stop, shutdown, failed updates, and installed-app upgrades. Stop only owned components and retain the explicit updater cleanup/error path.
- Until those pass, do not ship a new interception backend or claim verified simultaneous Clash TUN operation. The first requested installable library release uses the existing engine, native conflict guard and clear routing limitations.
- When the native iteration is complete, increment to an unused version, run the full required checks, publish the signed GitHub Release with the established updater key, verify it, and update this PC's separate `/proxyking/` LAN mirror. Preserve the HappyCheats server/task/configuration/files/firewall scope; report offline peers honestly.
